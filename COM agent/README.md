# 健康产品组合 Agent（大模型配比与复核）

## 2026-10-28 模型调用优化

首次完整流程通常调用4次：需求提取、批量选品、组合说明、最终复核；选品命中缓存或完整人工审核规则时可少一次。用户确认商品后，组合模型只返回商品ID和搭配依据，不再输出日量；程序按原标签或有效的本用户专业调整记录计算日量、成分及报价。旧的直接配比接口仍允许从候选商品中选择，日量同样只由程序计算。

需求提取新增 `kind`，区分明确补充需求与一般健康管理方向；旧记录仍可读取。组合摘要、搭配理由及报告建议全部纳入最终复核。复核输入以一份原始标签为主，保留所引用原文及警示；文字编辑会标明修改字段，同时保留原文、固定商品及必要的完整背景。人工案例模型提炼必须返回逐字来源引用，程序核验后写入规则依据；人工审核和启停流程不变。

只修改运费或优惠时，若新版本草案已有通过的复核、其他输入未变、重新计算未超预算或增加缺项，且说明文字不涉及费用，可沿用原复核。报告保留原复核时间，另记录费用重算时间。周期、预算、日期变化，旧版本草案、有提醒或失败的复核，或文字涉及费用时，仍重新复核；不会借费用更新放过禁用、超量或原有失败。

管理员在“使用历史 → 查看详情”的结果 `model_usage` 中查看各次调用的阶段、模型、耗时、输入/输出Token、缓存Token及失败类型。`cache_hit`、`rule_hit`、`review_reused` 表示本地复用，不是模型调用；`ok`表示模型接口返回成功，内容是否通过以当次业务结果为准。服务未返回Token时记为null，不估算为0；`input_chars`只是提示词及JSON数据的字符数，不是Token或计费量。日志不额外保存密钥、提示词或健康正文。取消/进程中断的未完成调用可能没有完整统计；不能把历史统计当作供应商账单。历史旧记录无此字段。

新增回归测试 `test_model_optimization.py` 使用虚构资料和模型替身，覆盖固定用量、摘要复核、费用复用边界、人工文字修改、规则引用及API/CLI统计。自动化测试不代表已验证真实模型的临床判断质量，也不代表已测得真实Token节省比例。

双击 **启动应用.cmd**，启动脚本会在后台运行服务，确认就绪后打开 http://127.0.0.1:8765 。关闭启动窗口或聊天不会停止服务。当前电脑直接使用Codex附带的Python；其他电脑需Python 3.11+并安装 `pip install -r requirements.txt`。如需停止，可在任务管理器找到启动时显示的PID并结束对应进程。

## 使用

1. 点击“载入示例”，再生成当前用户报告。虚构目标为蛋白质与维生素B6补充；A+C、30天的标签日量为1份+1片，程序核算购买费用217元、消耗成本172.50元。示例选填项保持留空，模型会因关键资料不足拦截，并提示需补充的信息；不会自动伪造完整健康背景。预算可留空，运费和优惠留空按0元计算。标有星号的字段为必填。
2. 在左侧“用户分类”点击“新增”，编辑姓名、编号和健康背景；已有用户点“编辑”修改信息。选择用户后，工作台的分析文字、审核信息、周期、预算、剂量调整和报告均归属该用户，切换后分别恢复。支持自由格式专业分析，无需添加“营养目标”等固定标题。
3. 选择“现有安利／纽崔莱资料”，或在“产品资料库”导入Excel。保留来源ID，不合并同名不同规格。
4. 点击产品“查看/核对”，补齐现售标签日量、包装、完整成分、过敏原、禁忌、依据和有效价格。原始Excel只读；导入与修改后的产品库保存在本机，可下载产品库JSON备份。
5. 工作台分四步：“分析资料 → 需求确认与选品 → 选品结果 → 组合报告”。点击分析资料下方的“提取健康需求”，核对目标及逐字原文依据，勾选本次目标后点击“确认需求并选品”。系统一次批量判断产品关联，最多展示10款有关联或待核验商品，包括目标对应、选品理由、标签日量、参考单价、原文依据和资料缺项。勾选本次使用的商品，再点击“确认选品并生成完整报告”；报告只使用已确认商品，不重复扫描整个产品库。组合不合理或资料不足时说明原因，不擅自增减商品。每日用量、成分和报价按原标签计算，独立 eval 通过或仅有待确认提醒时展示和导出报告；提醒保留在草案中。可返回前一步，输入和已完成结果保留；选品超时可直接重新选品。用户资料、提取、选品结果、商品勾选和报告保存在本机，刷新后恢复。修改资料后原输入与提取内容保留，可明确选择“沿用已提取需求”或“重新提取”，随后按最新资料重新选品。产品库更新后旧结果失效，历史仍可在管理后台查看。报告显示用户姓名、编号和目标原文依据，下载文件名包含编号；支持Markdown、JSON和浏览器打印PDF。载入示例会切换到独立示例用户。
6. 生成报告后，点击报告右上角“编辑报告”。可修改分析摘要、各产品搭配依据、生活方式及复查建议；产品、用量、成分合计和报价保留原计算结果。点击“保存并复核”后由同一模型重新检查文字与原分析、标签依据是否一致，通过或仅有待确认提醒时更新预览、下载和打印，并保存到本机；明确冲突、调用失败或取消时保留原报告。原专业分析保留，修改记录和当次复核提示词进入管理员历史。更改用户资料后不能编辑旧报告，需重新生成。

## 保存、恢复与费用调整

- 页面上方显示“正在保存 / 已保存 / 保存失败”。保存失败可重试或下载当前草稿；两个窗口修改同一用户时，后提交的冲突不会覆盖已保存资料。可先下载草稿，再点击“载入已保存资料，放弃本页修改”。有未保存内容时，关闭或刷新会触发浏览器提醒。需求勾选与商品勾选都按用户保存。
- 需求提取、选品、配比与复核在后台执行，显示当前阶段和已用时间。刷新后恢复进度；可取消任务。服务重启会将未完成任务标为中断，可手动重试。取消后不写入迟到的结果；已经发出的 API 请求可能仍需等待服务端结束，不能保证取消已产生的费用。
- 复核调用失败时，已完成的计算草稿保存在本机，但不能作为报告导出。点击“仅重试复核”可继续，无需重新选品或配比。输入、产品库、提示词或相关人工规则变化后，旧草稿不能直接重用。
- 只调整周期、预算、运费或优惠，会保留需求及已确认选品。点击“查看现有选品”，再生成报告；有可复用计算草稿时只重算用量总数、包装数、费用及约束，再单独复核。日用量仍按标签计算，预算不足不会自动换商品。健康信息、禁用商品或需求勾选变化时，仍需重新校验选品。修改产品资料后保留原文需求，重新选品时检查最新资料。
- 旧版本生成的报告没有后台草稿记录，首次费用调整仍需生成一次配比；后续可复用。人工修改过文字的报告也会重新生成搭配依据。

## 管理后台

独立入口：http://127.0.0.1:8765/admin ，也可点击工作台右上角“管理后台”。首次使用由本人设置管理员账号与密码，没有默认密码；密码需8至128个字符。创建后使用该账号登录。

- **用户**：查看所有本机工作空间保存的用户、健康分析、健康背景、禁用商品和使用次数；按姓名或编号搜索，进入对应使用历史。
- **使用历史**：查看需求提取、选品、配比与复核、报告文字修改与复核、产品库导入的时间、状态、输入、结果及当次提示词快照。可按用户筛选，分页查看。成功、拦截和失败均记录。
- **功能提示词**：只读查看需求提取、产品关联、组合说明、独立复核和人工案例提炼实际使用的五套提示词、版本与输出结构；本地规则功能标明不使用大模型。

管理接口在服务端校验独立管理员会话，未登录不能读取管理数据。密码使用加盐PBKDF2哈希保存，会话有效期8小时，退出后立即失效。普通工作台按浏览器工作空间隔离用户，不等同于逐用户登录系统；清除浏览器Cookie或更换浏览器会进入新的工作空间，旧资料仍由管理员查看。

数据库为本目录 `data/health.sqlite3`，保存健康资料、产品库、使用记录和管理员认证信息，不保存模型API密钥。如需备份，停止应用后复制该文件。此前仅保存在页面内存且已关闭的资料无法恢复。

## 产品Excel格式

支持现有归档格式，以及首行以“产品ID”“产品名称”开头的普通表。

| 列名 | 内容 |
|---|---|
| 产品ID、产品名称、SKU | 同一市场与包装的唯一产品 |
| 健康目标 | 用分号分隔，提供关联线索；不要求与用户目标同名 |
| 每日用量、单位、说明书每日最大量、包装含量 | 数字；日量和包装含量使用同一单位 |
| 标签来源、依据 | 现售版本、链接和关联依据 |
| 成分JSON | `[{"name":"钙","amount_per_unit":200,"unit":"mg","source":"标签版本/页码"}]` |
| 成分完整、审核状态 | `是`、`已审核`，只确认资料，非个体方案审核 |
| 过敏原、禁忌 | 分号分隔；没有填`无`；空白为未知 |
| 价格、币种、价格日期、价格有效期、价格来源 | CNY；YYYY-MM-DD日期；与SKU一致 |

现有40条归档记录按Excel补入健康方向、关联依据、可识别的包装含量、明确的非历史日量和有官方依据的每单位成分数值。产品核对页展示原表中的功能、适宜人群、注意事项、规格、用量原文、核验状态及来源；历史或未知成分保留原文，不转成确定数值。不同来源记录保留各自ID，不按名称合并规格。“每日1片”等历史自由文字不自动成为可执行剂量，建议日量不等于标签最大量。未提供的过敏原、标签上限、完整配方和价格有效期仍待补齐，导入不会自动勾选标签审核。没有价格有效期时不能作为当前报价。

当前按使用者要求，直接在这40条归档记录中补充Demo参数，名称、ID与原始Excel保留，不增加新库。已有字段优先保留，缺失日量按原表或剂型设置演示值；缺失成分、包装、过敏原、禁忌和报价使用明确标注的假设。蛋白粉80%蛋白质比例参考[安利官方资料](https://www.amway.com.cn/Content/newsBrandStrength/newsProduct/newsNutrilite/Key_Standards_for_Buying_Protein_Powder/news?channelId=100000257&contentId=2074421211336060929)，每日10克仍只是本次演示日量。益生菌的演示成分按制剂干粉质量计，不将质量当作活菌数；原表活菌信息保留。`demo_ready`仅表示演示参数齐全，`label_reviewed`与`ingredients_complete`保留真实状态。模拟上限等于演示默认日量，不是产品标签上限或人体摄入上限。演示报价使用原表参考价或假设值，日期和有效期也为假设，不是实时行情。网页显示“Demo参数齐全”，详情列出补充依据，输出标记示例报告。仍检查禁用商品、停用状态、过敏、禁忌、超量及预算，并保留独立复核；不会自动通过模型复核。

## 当前能力与限制

大模型先整理原专业分析已确认的需求，保留逐字原文依据，使用者确认后进入选品。结合产品资料判断需求关联，不以目标标签同名作为唯一门槛；不为销售商品改变原分析，也不从裸指标推导补充需求。用户禁用及停用商品在模型调用前排除。有关联但标签资料不完整的商品展示缺项，不直接进入配比。然后从经本地资料检查的候选库选品、生成每日用量与搭配依据，再独立复核选品、日量、禁用商品、重复成分与禁忌。本地规则负责原文依据核对、提取记录归属与版本检查、候选资料检查、禁用商品排除、标签用量校验、成分质量合计和报价。模型不能虚构商品或价格，也不能绕过本地校验。网页按标签日量计算，已移除其他成分摄入和个体剂量调整输入项；未提供的摄入资料保持待核验，输出仍需专业复核。

组合保持**待专业复核草案**。未接入专业药物相互作用库、实时价格、签名验证与临床发布。就医优先、儿童、已提供的累计摄入超上限时暂停搭配。未知摄入与药物不视为“无”。产品关联判断依赖提供的资料，最多召回10款候选，可能遗漏适用产品；配比考虑目标覆盖与重复成分，尚无全局预算最优搜索。

已确认选品后，膳食/能量评估不足、适用或合用依据待确认、部分目标未覆盖等提醒不再直接阻止报告。配比可返回带产品的`needs_review`草案；独立复核的`unknown`事项写入“组合提醒”，保留产品、标签日量、自动报价、编辑和导出。`unknown`不会被改成通过，也不代表合用安全性已确认。明确禁用、禁忌、剂量错误、超量、超预算和复核`fail`仍拦截；调用失败或无可计算产品时不生成报告。

默认无需另配API密钥：复用已登录的本机 Codex CLI 和配置模型，当前电脑为 gpt-6.1-sol。需求提取、产品关联、配比与复核使用独立提示词；提取与选品后分别等待使用者确认。选品是独立请求，生成报告时检查选品记录归属、版本、产品库和模型是否一致；配比与复核在同一请求内共用配置快照。Codex 非交互调用使用结构化输出、临时会话、禁用工具与只读沙箱，不读取当前聊天历史。产品关联的CLI推理强度为medium，超时300秒；其他阶段沿用当前配置，超时180秒。四个阶段均消耗账号模型额度。

几十款产品使用一次批量关联调用，输入去除重复归档摘要和无关链接，保留成分、适用人群、禁忌和历史资料限定，输出最多10款候选；后续配比只接收已确认且通过资料检查的商品，最终复核接收已选商品的关联依据和原资料。确认的选品记录保存在本机数据库，报告生成不重复调用选品；同一服务内相同分析、背景、关联资料及模型配置也可命中最多32组的内存缓存。输入变化后需重新选品，配比与最终复核不复用。单次批量输入仍随产品数量增长，不能保证固定用量或延迟。

健康分析原文、健康背景、产品标签和组合会发送到所选模型服务。结构化用户姓名/编号和原始Excel行不单独发送，但原文或依据中包含的个人信息仍可能发送。资料、报告和使用历史保存在本机数据库，也可手动下载；Codex使用临时会话，不保存CLI会话历史。仅监听127.0.0.1，管理后台使用独立管理员认证。模型与规则不能替代临床判断，也不保证发现所有风险。

## 共用模型配置

当前使用 Codex CLI，运行前确保 `codex login status` 显示已登录。未安装或未登录时不会跳过模型阶段，也不会改用本地规则直接输出。

切换 API：将 `.env.example` 复制为本目录的 `.env`，填写三项（留空时继续使用 Codex）：

```dotenv
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=在本机填写密钥
OPENAI_MODEL=支持结构化输出的模型名称
```

需求提取也使用同一套API配置。API 地址填到 `/v1` 等服务基址，不带 `/chat/completions`。配比与 eval 同时切换，使用相同地址、密钥和模型名称。API须支持 Chat Completions 的严格 JSON Schema 输出；不支持或仅填部分配置时会报错并拦截。修改配置后下一次生成生效，同一轮调用中配置保持一致。系统同名环境变量优先于 `.env`；密钥不返回前端，不写入报告，`.env` 不通过网页提供下载。

禁用商品在侧栏用户的“编辑”中填写，用分号分隔产品ID、SKU或完整商品名称；留空表示未设置。建议使用ID/SKU以区分规格。页面切换用户时禁用清单分别保存。本地按精确标识匹配，大模型另核对可辨认的同名商品；模糊名称无法保证正确匹配。

参考：[Codex 非交互运行](https://learn.chatgpt.com/docs/non-interactive-mode)、[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 人工案例学习

管理员进入“管理后台 → 人工案例学习”。录入匿名案例标题、专业分析、明确目标及背景、人工选用商品和实际日量、组合依据、排除商品与原因、使用反馈和局限。来源案例及商品快照保存在本机，作为不可变来源；更正案例可录入新记录。

“提炼规则”是管理员单独触发的一次当前模型调用，不在生成请求中提炼，不做微调。本案例及所选商品资料发送到当前模型，最多返回8条待审核的选品、组合或排除规则。也可从来源案例人工新增规则。修改适用条件、商品、依据和局限后保存，规则自动转为待审核；勾选审核确认再启用。支持停用、来源案例详情和逐版本操作记录，提炼提示词及历史保存在管理后台。

应用规则时，本地匹配已确认目标、年龄、疾病、用药、过敏与孕哺条件，不读取完整案例。不同条件组为AND，同组数组为OR；组合规则的目标必须全部满足，避免单个目标命中时引入其他目标商品。目标与背景名称按去空白及大小写归一后精确匹配，不做额外模型检索。未知背景不能匹配对应条件。最多提供8条相关选品/组合摘要和8条排除摘要，所有命中的排除商品均先在本地排除。商品的标签、成分、适用资料或禁忌变化后旧规则不再直接复用。

人工选品/组合规则足以覆盖当前全部目标，且相应商品通过本地标签与禁忌检查时，复用审核关系，省去批量关联模型调用；不足时回到批量关联。配比和独立eval仍执行，规则不是临床安全证明，也不保证降低每次耗时或Token。模型仅接收短规则摘要，报告及选品历史保留规则ID、版本与来源案例ID，管理员可追溯。选品后适用规则有修改、停用或新启用变化，须重新选品再生成报告。

规则不能新增库外商品、修改标签日量、套用历史实际日量、覆盖用户禁用商品或跳过剂量、过敏、禁忌、累计摄入及预算检查。客户端不能注入已启用规则；规则管理接口仅管理员可访问。运行 `python -m unittest -v test_learning test_admin` 验证审核生命周期、来源版本、未知背景、商品变更失效、调用次数、案例全文不进入生成上下文、排除优先、安全约束及管理员权限。
